## What to do next

**A real, severe bug was found and fixed after Epic 10: `window.ndx` (the entire typed IPC bridge) silently failed to exist in every build, on every screen.** `electron-vite` externalizes npm dependencies from main/preload builds by default — fine for the unsandboxed main process, but this app's preload runs **sandboxed** (`sandbox: true`), and a sandboxed preload's `require()` cannot resolve npm packages at all. The bundled preload shipped a bare `require("zod")` that threw immediately, aborting the script before `contextBridge.exposeInMainWorld` ever ran. Every screen's real "bridge unavailable" fallback masked this as normal-looking empty/error states, and the existing e2e test only checked visible shell chrome that renders identically either way — so nothing caught it until the packaged app was actually launched and its console inspected. **Fixed** in `electron.vite.config.ts` (`preload.build.externalizeDeps.exclude: ['zod']`) and **guarded against regressing** by a new first assertion in `e2e/app.spec.ts` (`typeof window.ndx === 'object'`) — verified to actually fail without the fix. See the Epic 10 ledger entry's "A real, production-relevant bug found and fixed" section for the full diagnosis. **Any future dependency added to `src/preload/index.ts` or anything it imports (including all of `shared/contracts/`) must be added to that same `exclude` list, or it will silently break the bridge again.**

**A second, unrelated real bug was found right after: the UI didn't render at all in `npm run dev` specifically.** `src/renderer/src/app/routing/routes.tsx` had `import { lazy, Suspense } from 'react'` sitting as the literal last line of the file, after every `lazy(...)` call that uses it — Vite's per-module dev transform (React Fast Refresh) hit a real temporal-dead-zone crash on this (`Cannot access 'lazy' before initialization`) that the production Rollup build happened not to expose, which is why the first fix's production-build verification didn't catch it. **Fixed** by moving the import back to the top of the file with the rest of the imports. **Diagnosed** the same way as the first bug — Playwright's `_electron` launcher with a `pageerror` listener — but pointed at the actual running Vite dev server (`http://localhost:5173`), not the packaged build, since that's the only way to reproduce a dev-mode-only crash. See the Epic 10 ledger entry's second "A real bug found and fixed" section. **Lesson: a fix verified only against `npm run build` is not automatically verified for `npm run dev` when the bug is bundler-order-sensitive — reproduce and verify in whichever mode the bug actually occurs.**

**A third gap was found right after that — not a crash, a real UX/discoverability defect: "icons are missing and some screens also."** Both halves of that report were genuine. (1) The Primary Navigation Rail rendered the exact same generic gray-dot placeholder for every one of its 11 destinations — there was never a real per-destination icon, so the rail's collapsed icon-only state (the default at Steam Deck width) was genuinely unusable. **Fixed** with a real hand-authored inline-SVG icon set, one distinct icon per destination (`components/navigation/navigationIcons.tsx`, no new dependency), wired through a proper `NavigationIcon` component. (2) Several real, working, already-tested screens — Controller Settings, Display and Theme Settings, Privacy and Permissions, Power Menu, About and Diagnostics, Recovery Timeline, Storage and Recovery, and Agent Operations Center — had **no path to them anywhere in the UI**, only by typing a route by hand. The wireframe spec's 11 primary destinations make "System" the sole entry point for the System-area screens, but `SystemDashboard.tsx` never actually linked to any of them. **Fixed** by adding a real "Settings and tools" section to the System Dashboard linking to all eight, plus a link from Workflow Library to Agent Operations Center (the spec's own staging plan groups Workflows and Agents together; Agents has no primary-rail destination of its own). **Lesson: a screen being real, built, and passing its own tests does not mean a user can reach it — always verify the actual navigation path, not just the route's existence.** See the Epic 10 ledger entry's third "A real gap found and fixed" section.

Add new methods to the `NdxBridge` interface in `shared/contracts/bridge.ts` and new channel names to `ipcChannels.ts`.
16. **Any new fetch-on-mount effect must avoid `react-hooks/set-state-in-effect`** — don't call a function (or inline code) that sets state synchronously before its first `await` directly in an effect body; either inline the fetch so all `setState` calls are inside the `.then()`/await continuation, or seed the initial state from props/dependencies instead of imperatively flipping it back in the effect, or give the state a new-object-reference field (e.g. a nonce) instead of nulling it out. This lint rule's static analysis doesn't reliably trace through `useCallback`-wrapped async functions called from an effect — when in doubt, inline the fetch. 18. **When testing code that submits through the real `ActionQueue`** (workflow tool-action steps, or anything else built on it), remember `submit()` parks ungranted capabilities as `pending-approval` and never auto-executes — grant the capability first in test setup (or call `queue.approve()`) if the test expects auto-execution. This is correct, intentional `ActionQueue` behavior, not a bug — see the Epic 8 ledger entry's "A real bug found and fixed" section.
19. **Steam Input / native adapter remains an open gap** — physical Steam Deck rear grip buttons (L4/L5/R4/R5), Quick Access, and the Steam button aren't reachable via the standard Gamepad API. Revisit if/when that becomes a priority.
20. **No boot-critical service check may hard-fail the whole UI just because its own data came back empty, unreadable, or the call itself rejected.** `BootSessionStart.tsx`'s workspace check used to do exactly this and permanently walled users out behind a "Boot failed" screen with no way back in (Retry just re-reads the same bad state) — fixed by treating it like the already-optional model/controller checks. `JsonStore.read()` also now self-heals a genuinely corrupted file (quarantines it, returns the default) instead of throwing, since it backs ten different stores and any one of them could hit this. A _second_ pass was needed: a resolved `{ ok: false }` result and a _rejected promise_ are different failure shapes, and `runStep()` only guarded the first one — a rejected IPC call (no handler registered, a main-process crash) silently aborted the rest of `runBoot()` with no further state updates, leaving the step stuck on "running" until the unrelated 15s global timeout. `WorkspaceProvider.tsx`'s mount effect and `refresh()` had the identical gap (a `.then()` with no `.catch()`, an `await` with no `try`/`catch`) and could leave the workspace-scoped UI spinning forever post-boot too. Both are now hardened with `try`/`catch`/`.catch()`. When adding a new boot-time or data-fetching check, ask "is an empty/failed/rejected read here actually fatal, or just a normal degraded state — and have I handled _both_ failure shapes a promise can produce?" See the Epic 11 ledger addendum "boot permanently blocked by a non-fatal workspace read failure" (plus its follow-up section) for the full writeup, including a real test-authoring gotcha (`vi.fn().mockRejectedValue()` pre-creates the rejection at setup time, not call time — use `vi.fn(() => Promise.reject(...))` instead).

## Risks and constraints to carry forward

- **No mocked completion is acceptable anywhere.** A coding agent must not report a screen, service, or epic complete based on routes, UI scaffolds, static cards, or mocked data. Completion requires real services, typed IPC, controller traversal, failure states, tests, and ledger evidence.
- **Controller-first is a hard requirement, not a stretch goal.** Every feature must be fully usable with a controller alone from the moment it ships; touch/mouse are optional accelerators only.
- **AI destructive actions always require the full review pipeline** (Intent → Plan → Policy → Permission → Review → Typed tool call → Validation → Audit → Recovery checkpoint) — this pipeline is real (`ActionQueue`), and strict Agent Runtime `toolCalls` now flow into it through the renderer-owned bridge with allowlist and permission-ceiling checks. Future agent capabilities must continue to reuse this exact pipeline, never a separate weaker one.
- **Offline-first is non-negotiable** for the systems listed in supplemental §3.6 (shell nav, local workspaces, files, terminal, local Git, installed local models, local search, local workflows, controller settings, recovery, installed docs).
- The wireframe spec outranks the implementation prompts whenever they conflict — see the precedence order in `CLAUDE.md` §2.
- **Tracked, accepted risk:** `npm audit` reports 5 vulnerabilities, all confined to Vitest's dev/UI server dependency chain (devDependency only, never packaged). Revisit at the Epic 12 security pass — see `docs/security/NDX_SECURITY_ARCHITECTURE.md` §7.
- **Typed cross-process IPC (§14) is now real** (Epic 5) — `shared/contracts/`, `src/main/ipc/`, `window.ndx`. Follow this established pattern for every future main-process-needing feature.
- **Steam Input gap (Epic 2):** physical controller access to `voice`/`keyboard`/`ai.actions`/`execute` and 6 of the 9 spec'd chords requires Steam Input or a native adapter that doesn't exist yet — documented, not silently missing.
- **Epic 3 is 11 of 12 screens real now — only ND-002 Lock Screen remains deferred**, blocked on a real profile/credential vault (Phase B's Epic X10, not yet built) and Agent Runtime's workflow-pause state (which exists now for agents but Lock Screen itself isn't wired to it). Don't build it with fabricated data.
- **Epic 4's deferred ND-013 AI Command Canvas is now unblocked by Epic 9's real Model Router** — it still needs an inspectable ActionPlan-conversion/review screen built; don't fabricate the AI side, the real model is there now.
- **Epic 5's `write()` and `delete()` are real; copy/move/rename/compress/extract remain deferred** — each touches two paths (a source and a destination) or an archive boundary, and needs a real multi-path checkpoint shape beyond the single-path `file-write`/`file-delete`/`git-restore` kinds this slice built.
- **Epic 6's Git restore/discard/branch-delete/force-push are real now** — `RecoveryService` gained a `git-restore` checkpoint kind alongside `file-write`, and the force-push/force-delete paths each have their own explicit, separately-confirmed irreversibility-warning dialog. `Git recovery branches` (a real branch created at the current commit as a safety net, distinct from the Recovery Service checkpoint mechanism) is also real now — created through the same createGitBranch IPC, named with a recovery/ prefix the UI filters on.
- **Epic 7's Build Studio is complete for Phase A scope**: save, structural edits, and reviewed predictive editing are real. Voice-to-code and debug/test/task-runner integrations remain future services, not Epic 7 completion blockers.
- **Epic 11 (System integration) is fully complete — all 16 screens are real.** Each still has its own honest internal scope limits (e.g. Network/VPN management actions, Integrations' account/lifecycle management, Updates' download/apply/rollback, and Quick Access' Steam Deck hardware button are all real-but-read-only or deferred within an otherwise-real screen) — check the checklist's per-item notes before assuming a specific sub-feature exists just because the screen itself is real.
- **Privacy and Permissions' "matrix" is per-tool, not per-actor** — `PermissionBroker` grants a capability broker-wide; there's no way to show "agent X has Y but tool Z doesn't" without adding per-actor grant tracking to the broker first, which would also change Epic 4's permission evaluation semantics — don't bolt that onto the privacy screen without revisiting the broker itself.
- **`BrowserSessionService` is the first service in this codebase that cannot be unit-tested in Vitest** — it needs a real, running `app.whenReady()` `BrowserWindow` to create a `WebContentsView` at all. Keep new browser logic that _can_ be pure (URL policy, tab metadata, anything not directly touching `WebContentsView`) factored into separate, unit-tested modules the way `browserUrlPolicy.ts`/`BrowserTabStore.ts` already are — don't let untestable logic creep wider than it has to.
- **Epic 10's Browser System only keeps one tab's `WebContentsView` resident at a time** — switching tabs closes the previous tab's `webContents` and recreates fresh on reactivation. This is a deliberate scope simplification (not a leak), but it means tab state (scroll position, in-page form data, etc.) does not survive a tab switch — don't claim full multi-tab session persistence without revisiting this.
- **`electron.vite.config.ts`'s preload `externalizeDeps.exclude` list is load-bearing, not cosmetic.** Any npm package newly imported into `src/preload/index.ts` or transitively via `shared/contracts/` must be added to it, or the sandboxed preload's `require()` will throw and silently disable the entire `window.ndx` bridge again — every screen's real fallback UI will make this look like "no workspace"/"bridge unavailable" rather than an obvious crash. Always sanity-check a real packaged launch (not just unit tests, which stub the bridge) after preload dependency changes.
- **Remote Systems (ND-040/ND-041) is real for SSH terminal sessions only** — file browsing, a command builder, non-SSH targets, metrics, logs, port forwarding, and remote desktop launch are not built; don't assume any of those exist. `RemoteConnectionService`'s trust-on-first-use host-key logic is unit-tested against a fake `ssh2.Client`, not a live SSH daemon — there is no automated live-server connectivity test, only manual verification. **Learning Hub/Guided Lab (ND-038/ND-039) remain completely untouched** — don't assume any learning content exists.
- **Display and Theme Settings only persists reduce-motion/high-contrast overrides and a text-size scale** — Appearance (no light theme), Transparency (no glass/blur effects), Focus style (no alternate ring), Wallpaper, and OLED-safe behavior each need a real visual system built first, not just a settings toggle wired to nothing.
- **Controller Settings only persists haptics intensity** — button remapping, app profiles, and the rest of ND-043's sections need either the `gamepadPolling.ts` config-threading refactor or Steam Input/a native adapter (the same documented gap as Epic 2's rear-button/gyro/trackpad limitation).
- **Power Menu intentionally never implements real OS-level suspend/reboot/shutdown** — not behind a flag, not stubbed, just absent. Those are irreversible against the whole host machine, not just this app. If this ever becomes a real requirement, it needs its own native-integration design and the user's explicit sign-off before any code is written, not just before it's wired to a button.
- **Epic 8's Workflow Engine is real; Agent Runtime's core lifecycle, typed IPC, UI (ND-016/ND-017), ActionQueue-backed tool submission bridge, run pause/resume, child-agent bounds, and dry-run are now real too.** Strict model-emitted JSON toolCalls can now flow through agentTool.request into the renderer-owned ActionQueue, with allowlist and permission-ceiling checks. Pause/resume prevents the next tool submission and is exposed in Agent Detail. Child-agent proposals are parsed and rejected against persisted policy rather than ignored. A real, persisted dryRun flag still plans through a real model completion but never submits a tool call to ActionQueue, recording what would have run instead — exposed via a real checkbox and `[Dry run]` badge in Agent Detail. The Detail screen's Files/Tools/Permissions/Logs tabs are still absent because the dedicated per-run tab data model/UI is not built yet. Don't claim Agent Runtime or Epic 8 complete until richer run tabs/logs and end-to-end UI coverage land.
- **The Workflow Engine is sequential, not a graph executor** — Script, Parallel branch, Merge, and Rollback node types are not implemented. AI decision is unblocked by Epic 9's real model router but not yet wired into the engine. Don't add the graph-only node types without first expanding the run model (currently a flat ordered list of steps) to support branching/looping/concurrency.
- **Epic 9's Model Router is complete for OpenAI-compatible chat and managed Ollama endpoints; non-OpenAI-compatible modalities (vision/speech/TTS/embeddings) and usage/cost accounting are not.** Don't assume a provider-reported capability matrix beyond what `/models` actually returns — NeuroDeck never infers capability/context-size/pricing from a model name.
