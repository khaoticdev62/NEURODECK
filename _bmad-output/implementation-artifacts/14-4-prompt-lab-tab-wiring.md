# Story 14.4: Wire the 15-prompt pack into the in-app Prompt Lab tab (PromptDrive)

Status: pending

## Story

As a User of the NEURODECK app,
I want the 15 specialist prompts selectable directly from the **Prompt Lab** tab,
so that I can browse, preview, and copy/save them without leaving the running app or knowing they live in `docs/prompt-system/prompts/` at all.

## Acceptance Criteria

1. `assets/prompt-packs/production-code-prompt-system.json` exists, auto-discovered by `promptdrive::load_builtin_packs()` (which already reads every `*.json` in `assets/prompt-packs/` — no Rust code change needed for discovery), containing one `PromptTemplate` per specialist prompt (15 total), each holding the full prompt text verbatim plus a single optional `task_context` slot for appending project-specific notes.
2. The pack (`production-code-prompt-system`) and its 15 template IDs do not collide with the existing `core`/`coding.production` packs — verified by a real test that calls `load_builtin_packs()` and asserts on the loaded pack/template counts and IDs (not just static JSON inspection).
3. The pack is generated by `scripts/promptpack/generate-production-prompt-pack.mjs` from `docs/prompt-system/prompts/*.md` (the canonical source) — re-running the script after any future prompt update keeps the in-app copy in sync rather than letting it silently drift.
4. From the running app: opening the Prompt Lab tab, selecting the new pack, choosing a template (e.g. "03 — Security Hardening + OWASP"), and using the existing preview/copy/save actions all work without errors — including with the largest template (~41 KB), confirming the existing slot-validation/preview/textarea UI doesn't choke on a mega-prompt-sized template.

## Tasks / Subtasks

- [ ] Write the generator script and run it to produce `assets/prompt-packs/production-code-prompt-system.json`.
- [ ] Add `promptdrive::tests::loads_and_validates_real_builtin_packs` (a real, file-system-backed test, not a synthetic fixture) asserting all 3 built-in packs load and the new pack has exactly 15 templates.
- [ ] Run `cargo test --lib promptdrive::` and confirm it passes.
- [ ] Manually exercise the Prompt Lab tab in the running app per AC4 (requires launching the Electron app — not yet done as part of this story; flagged as outstanding manual verification).
- [ ] Wire `npm run prompt-pack:generate` in `package.json` so the sync step in AC3 is a documented one-liner.

## Dev Notes

- `promptdrive.rs`'s `prompt_pack_dir()` resolves to `<repo>/assets/prompt-packs/` via `CARGO_MANIFEST_DIR` at compile time — confirmed this is where the file needed to live for auto-discovery to work, no backend code changes required.
- `coding.production.json`'s templates are small, slot-heavy micro-prompts; these 15 are the opposite shape — large, mostly-fixed mega-prompts. Resisted forcing them into the small-slot-template style; one optional context slot is enough.
- The actual in-app manual click-through (AC4) has not been performed yet in this session — `cargo test` proves the backend loads/validates the pack correctly and `frontend:typecheck`/`frontend:build` both pass with no code changes needed on the frontend side, but a real "open Prompt Lab, click through a 41 KB template" pass is still outstanding and should happen before this story is considered fully done.
